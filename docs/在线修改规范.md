# 在线修改规范

本规范适用于**没有安装 Node 环境**、或**只做快速修改**（错别字、补充说明、更新过期标记）的贡献者。全程在浏览器完成，无需 clone 仓库。

## 1. 入口

打开任意文档页面，点击右上角 **"在 GitHub 编辑此页"**（铅笔图标）。

这会跳到 GitHub 在线编辑器，路径形如：
`github.com/QianLi2027/concise-guide-to-debugging/edit/main/src/content/docs/...`

## 2. 修改流程

### 2.1 直接编辑（仅限协作者）

如果你有仓库写权限：

1. 改完后滚动到页面底部 **"Commit changes"**。
2. **Commit message** 按《提交规范》第 3 节填写（如 `fix(通信协议): 修正 RS485 波特率笔误`）。
3. 选 **"Commit directly to the main branch"**（仅限错别字/格式；**技术内容修改必须走 PR，见 2.2**）。
4. 点 **"Commit changes"**。

### 2.2 提 PR（推荐，所有技术内容修改）

如果你**没有写权限**，或修改涉及**技术内容**（改参数、改步骤、改结论）：

1. 改完后滚动到页面底部 **"Propose changes"**。
2. **Commit message** 同上规范。
3. 选 **"Create a new branch for this commit and start a pull request"**。
4. 分支名自动生成为 `<用户名>-patch-<序号>`，可接受默认。
5. 点 **"Propose changes"** → 跳转到 PR 页面 → 填 PR 标题（同 commit message 规范）→ **"Create pull request"**。

## 3. 在线编辑能做什么 / 不能做什么

| ✅ 能做 | ❌ 不能做 |
|---|---|
| 修改 Markdown 正文 | 上传图片（需本地 `git add` 或用 GitHub 网页上传文件功能） |
| 修改 front matter 字段 | 新建文件（需本地或用 GitHub 网页 `Add file`） |
| 更新 `lastUpdated` / `outdated` | 移动文件到其他分类目录 |
| 修错别字、补链接 | 修改站点配置（`astro.config.mjs` 等） |
| 补充"验证"章节的实测数据 | 修改 CI workflow |

> **需要上传图片？** 在 GitHub 仓库页面点 `Add file → Upload files`，把图片传到 `src/assets/images/<分类>/`，然后在文档里用相对路径引用。**单张不超过 2 MB**。

## 4. 在线修改的 CI 兜底

你提交后，CI 会自动跑：

1. **front matter 校验**：缺字段、类型错误会**直接失败**，PR 不能合并。
2. **图片引用检查**：如果正文引用了不存在的图片路径，会**直接失败**。
3. **构建**：确保你的 Markdown 语法能被 Starlight 正确渲染。

**如果 CI 红了**：点 PR 页面的 `Details` 看日志，找到 ❌ 开头的错误行，按提示改。改完直接在 PR 分支上再 commit，CI 会自动重跑。

## 5. 在线修改的 front matter 注意

在线编辑器里 YAML 头是纯文本，**缩进必须是 2 个空格**，不能用 Tab：

```yaml
# ✅ 正确
authors: ['cmz488']

# ❌ 错误（Tab 或 4 空格会导致 YAML 解析失败）
authors:
    - 'cmz488'
```

**修改技术内容后**，记得顺手把 `lastUpdated` 改成当天日期（格式 `YYYY-MM-DD`）。

## 6. 什么时候不要用在线编辑

- **新增一篇完整文档**：在线编辑器只能改单文件，无法同时建目录、传图片、预览渲染效果。**改用本地 `pnpm dev`**。
- **大批量修改**（改 5 篇以上）：在线编辑每个文件要单独 commit，会产生大量碎片 commit。**改用本地一次性提交**。
- **需要本地验证排障步骤**：如果修改涉及"按这个步骤能不能复现"，必须在本地环境实际验证后再提交。

## 7. 在线修改后的跟踪

- PR 提交后，`maintainers` 里列的人会收到 GitHub 通知（如果他们在 `Watch` 这个仓库）。
- 如果 48 小时没人 review，在 PR 里 `@` 任意一个 maintainer。
- 合并后约 2-3 分钟，线上站点会自动更新（GitHub Actions 部署 Pages）。
